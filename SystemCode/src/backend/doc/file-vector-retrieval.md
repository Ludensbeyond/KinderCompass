# Standalone parent-guide retrieval (step 4)

`pipeline/parent_guide_retrieval.py` implements the typed
`GeneralKnowledgeRetriever.search(question, limit=3)` boundary. Construct one
`ParentGuideRetriever` per worker: it loads the validated active index once.
The [backend integration guide](file-vector-service.md) documents service
construction and routing added in step 5. Curated remains the default mode.

Run a read-only query from the repository root without a server:

```bash
PYTHONPATH=SystemCode/src/backend:SystemCode/src/backend/pipeline \
  .venv/bin/python -m SystemCode.src.backend.scripts.query_parent_guide \
  'How do subsidy thresholds change in 2027?' --mode lexical
```

Use `--mode vector` to embed only the question with the configured OpenAI model,
1536 dimensions and eight-second timeout. This needs network access and the
existing `OPENAI_API_KEY`; `.env` loads without overriding shell settings. The
query uses one provider attempt, with SDK retries disabled. Document vectors
are never regenerated by querying. `--mode curated` selects the old corpus.
`--vector-path`, `--limit`, `--topic` and `--year` allow standalone inspection.
Topic accepts an exact reviewed topic, section heading or mapping ID.
Queries longer than the configured maximum (default 2,000 characters), empty
queries and zero limits return no evidence without a provider call.

Vector ranking is exhaustive cosine similarity on normalised float32 vectors,
with at most three results. Scores are used internally for ranking, not exposed
as confidence values. A provisional minimum of 0.40 was calibrated using eight
labelled guidance questions and six unsupported questions on the checked-in
build. Positive top scores ranged from 0.4221 to 0.6709; unsupported top scores
ranged from 0.0629 to 0.2978. This small sample establishes standalone acceptance,
not the comprehensive all-section evaluation required in step 6.

Explicit years and topic constraints filter reviewed metadata before ranking.
Fee/policy/intake years stay distinct from source-fetch and review dates.
Effective date intervals are honoured; an effective-from policy without an end
is not assigned an invented expiry. Undated background passages can accompany
dated results. Questions without a year can retain both 2026 and 2027 tables,
with policy-period labels prepended to preserve the distinction. Explicit
subsidy subjects constrain the infant/childcare mappings, while KCare/KiFAS
remain separate; CDA subjects constrain the current/package mappings.

If the index is missing, corrupt or incompatible, freshly hash-validated source
selections supply lexical retrieval. If those inputs fail validation, only the
curated fallback remains. Query model mismatch, invalid vectors, timeouts and
provider failures also fall back to guide lexical search. Low cosine relevance
triggers the same fallback. Lexical ranking uses existing BM25 helpers separately
from vectors, with a 0.45 coverage cutoff; years are used as metadata constraints,
not as evidence of relevance. The word “threshold” maps to HHI for guide tables.
No hybrid ranking was added: both independent modes retrieved expected passages
in the top three for all eight labelled questions.

Guide lexical failure then tries the injected curated retriever. Explicit year
or topic constraints suppress curated fallback because the existing curated
metadata cannot enforce those constraints. If neither corpus supplies relevant
evidence, `search` returns an empty list for the existing unavailable-evidence
response. The CLI defaults to lexical mode and supplies the existing curated
index; programmatic callers must inject their curated adapter.

Returned passages preserve tables, qualifications, evidence classification and
reviewed HTTPS citations with actual source-fetch timestamps. CCTV, waitlist and
section 11 material remain excluded as recorded in the source review. Retrieval
status contains only build ID, mode, timing, count and failure category. Provider
error details are suppressed; no question is stored or operationally logged.
The read-only CLI explicitly prints retrieved public guide passages.

Verification uses real hosted query embeddings plus deterministic query-vector
doubles for ranking, period filtering, bounded calls, corrupted/missing/model
mismatch recovery, timeout/invalid response recovery and fallback order. Eight
labelled positives passed in both modes; four unrelated and two corpus-excluded
questions returned no evidence. See `tests/test_parent_guide_retrieval.py` for
labels and the implementation plan for full-suite results. Build and rollback
commands remain in [index construction](file-vector-index.md); changing CURRENT
requires constructing a new retriever or restarting the worker.
